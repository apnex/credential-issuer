# credential-issuer

The contract of record for credential-issuer: what a consumer can depend on, admitted to zorg's component set by the director's rulings `D38` and `D39` in zorg's `docs/DECISIONS.md`; its vision is ratified (zorg's `D40`), and its design is specified in `CIss1` to `CIss5` below (zorg's `D47`, `D59` to `D63`, `D71` to `D73`).\
It also carries the fields of a mission-kit registry entry, and that entry is generated from this file, never written as a second copy.\
Admitted to mission-kit's component registry as `C10`, its first release `0.1.0` (`docs/DECISIONS.md` `D3`); its frontmatter is the entry's.

## Duty

Issue the credentials a caller presents to reach a hub, from authority the host accepts.

---

## Contract

What a consumer can depend on, one capability per row.\
A capability is named for what it offers, not for who offers it, so two components that provide the same capability share its name, and the overlap is visible.\
**Provides** means this component implements the capability; **carries from X** means it passes X's capability through its own interface.\
**Requires** names the capabilities of other components a row depends on, as `component:capability`, so a census can follow an application's demand down through the components it reaches.\
A capability of another component marked *asked* does not exist yet and is requested of it.\
The trait column names any trait a system takes on by using the capability.

| Capability | Relation | Requires | What a consumer can depend on | Trait |
|---|---|---|---|---|
| `standing-code` | provides | `caller-identity:verified-principal`, `shape-check:plain-json-value` | A person the host's verifiers prove signed in can mint a code for an identity the host's rule lets them hold, shown once and kept only as a hash, list the codes they hold, and revoke one; a revoked or expired code yields no admission key from the moment it is revoked or expires. | `T1` when codes are kept durably |
| `admission-key-issue` | provides | `caller-identity:verified-principal`, `shape-check:plain-json-value` | A caller proving itself with a sign-in the host's verifiers accept, or with a standing code, whose principal the host's rule allows for the hub it names, is given a key naming that principal, that hub and the caller's node, usable once and for about a minute; an admission key is never accepted as proof for another; a refusal gives no key and a reason. | none |
| `fresh-key-per-dial` | provides | `agp:dialer-credential-source`, `shape-check:plain-json-value` | Before every connection a client's connection holder opens, a reconnection included, it obtains a new key with the proof the application supplies, presents it once and only to the hub it names, and keeps it no longer; it presents a standing code only to the issuer; a failure to obtain a key ends that attempt with a reason, and nothing is dialled. | none |
| `single-use-admission` | provides | `agp:peer-identity-evidence`, `agp:admission-credential`, `agp:session-close`, `shape-check:plain-json-value` | An admission key admits at most one session, whoever presents it first; every later use is refused and reported, and while the key is live the session that used it first is named to the host, which closes it through the transport; a key for another hub or another node, an expired key, a standing code, and a key issued before the redeemer last started are refused. | none |
| `admission-key-verifier` | provides | `shape-check:plain-json-value` | Given one of its own admission keys and the admission's context, the redeemer answers as a verifier the host gives caller-identity: the principal the key was issued for, proved, with its issuer, or a refusal with a closed reason; caller-identity, not this component, records the session's principal, and the verifier never returns the key or any secret in it. | none |
| `preshared-key-secret` | provides | `agp:preshared-key-resolution` | On a pre-shared-key path, an admission key carries a fresh secret that the hub resolves from the key's identity without completing anything, so the handshake proves possession and the secret never crosses the wire; seeing a key's identity never uses the key. | none |
| `key-reuse-report` | provides | none | Each refused second use is reported once, to a sink the host supplies, with a fingerprint of the key, its principal, hub and node, and both sessions; never the key, its secret or the proof that obtained it. | none |

Admission keys and their single-use records are held in memory for about two minutes, so only `standing-code` brings a trait, and then only where codes are kept durably.\
It coordinates no actors and contains no model.\
Its shapes are OAuth 2.0's wherever one fits and is cheap (zorg's `D39`): the JWT access-token profile's claims for a key that is a token (RFC 9068), a token endpoint's behaviour for the issuing route, token exchange for a sign-in (RFC 8693), a client-credentials-style request for a standing code, and OAuth's bearer rules where a key is a bearer (RFC 6750).

**Two limits, stated with the capabilities (zorg's `D39`, amending `D38`).**\
A revoked sign-in stops new keys at once only where the application keeps a record of revoked sign-in sessions for the issuer to consult, since a sign-in assertion checked offline cannot see a logout.\
A second use closes the first session only while the key is live; afterwards it is refused as expired and reported, with nothing to close by.

## Design

Each declaration names the exit criterion that proves it and the contract test files that exercise it (`D10-E2`).\
A bounded identifier (`issuer`, `principal`, `instanceBinding`, `redemptionId`, `session`, `hub`, `codeId`) is a string of 1 to 256 Unicode scalar values (`Array.from(value).length` from `1` to `256`) containing no control character (`U+0000..U+001F` or `U+007F..U+009F`) and no lone surrogate (`U+D800..U+DFFF`), with `issuer !== "agp-transport"`; a machine or proxy `identity` matches `/^[a-z0-9][a-z0-9-]{0,62}$/` (`EM1`), and a `node` matches `/^([a-z0-9][a-z0-9-]{0,62})\.([0-9a-f]{16})$/` (`PX1`, `D60`), whose prefix before the dot is its claimed `identity`.\
`createCredentialIssuer(options: CredentialIssuerOptions): CredentialIssuer` validates `options` at construction (throwing `TypeError` on invalid options):
- required `hub: string` (valid bounded identifier) and `verifiers: readonly CredentialVerifier[]` (validated through `@apnex/caller-identity`'s `verifyCredential` plain-object rules);
- optional `standingCodeStore?: StandingCodeStore` (default `createMemoryStandingCodeStore()`), `allowStandingCode?: (input: { readonly minterPrincipal: string; readonly minterIssuer: string; readonly identity: string }) => boolean | Promise<boolean>` (default `({ minterPrincipal, identity }) => minterPrincipal === identity`), `allowAdmissionKey?: (input: { readonly principal: string; readonly issuer: string; readonly hub: string; readonly node: string; readonly proofKind: "sign-in" | "standing-code"; readonly proofMode: "native-tls13-external-psk-v1" | "bearer" }) => boolean | Promise<boolean>` (default `() => true`), `isSignInRevoked?: (input: { readonly principal: string; readonly issuer: string; readonly session: string | null }) => boolean | Promise<boolean>`, `onKeyReuse?: (report: KeyReuseReport) => void`, `clock?: ClockPort` (default `defaultClock` in `src/clock-adapter.ts`), `wallClock?: { nowMs(): number }` (default `{ nowMs: () => Date.now() }` in `src/clock-adapter.ts`), and `randomBytes?: (byteLength: number) => Uint8Array` (cryptographically secure random byte source defaulting to `globalThis.crypto.getRandomValues(new Uint8Array(byteLength))` in `src/clock-adapter.ts`, validated on each call to return a `Uint8Array` of exact `byteLength`, never substituting predictable counters, timestamps or identifiers);
- optional positive finite numeric bounds: `keyLifetimeMs` (default `60_000`), `keyRetentionMs` (default `120_000`, required `>= keyLifetimeMs`), `reconnectGraceMs` (non-negative finite, default `60_000`), `maxActiveLeases` (positive integer, default `1_024`), `maxHandlesPerLease` (positive integer, default `16`), `maxTotalHandles` (positive integer, default `4_096`), `maxRetainedKeys` (positive integer, default `maxTotalHandles`), and `maxPskIdentityBytes` (integer `1..127`, default `127`);
- returns a frozen `CredentialIssuer` `{ readonly hub, readonly generation, readonly clock, mintStandingCode, listStandingCodes, revokeStandingCode, issueAdmissionKey, readonly redeemer: { resolvePsk, completePskProof, beginPskArrival, redeemBearer, verifyRedeemed, sweepLeases }, resolvePsk, completePskProof, beginPskArrival, redeemBearer, verifyRedeemed, sweepLeases }` (exposing the redeemer methods on both `issuer.redeemer` and `issuer` so either can be passed directly as `redeemedVerifier` to `@apnex/caller-identity`).\
Every JSON-valued result returned by a host callback (`allowStandingCode`, `allowAdmissionKey`, `isSignInRevoked`, `StandingCodeStore.load`, `recordAdmissionRedemption`, `readAdmissionUse`, `readAdjacencies`, `notifyCredentialChange`, and the JSON fields of `issueKey`) after any declared native `Promise` completion is read as plain data through `shape-check`'s `readPlainJson` and `observePromises` (zorg's `D54`, `D55`), never invoking a getter or non-native thenable and consuming any reachable native promise rejections within the reader's bound; for `issueKey` (`CIss2`, `CIss5`), the 32-byte PSK secret crosses the plain-JSON wire boundary as `secretHex` (64 lowercase hexadecimal digits `[0-9a-f]{64}` validated by `readPlainJson` and decoded into a fresh `Uint8Array(32)`) and in-process as an optional own enumerable `Uint8Array(32)` data property `secret` whose bytes must equal `secretHex` when both are present (so `issueKey: (req) => issuer.issueAdmissionKey(req)` composes directly without any private adapter).

**CIss1 - Standing codes and durable storage (`standing-code`, `D38`, `D39`, `D54`, `D55`, `D73`).**\
Standing codes use the restart-stable `wallClock` (`nowMs(): number`) for `createdAtMs`, `expiresAtMs` and `revokedAtMs` (`expiresAtMs !== null && wallClock.nowMs() >= expiresAtMs` is expired), while admission keys and leases use the shared monotonic `ClockPort`.\
A `StandingCodeRecord` is a plain object `{ codeId, codeHash, identity, minterPrincipal, minterIssuer, createdAtMs, expiresAtMs, revokedAtMs }` where `codeHash` is the 64-character lowercase hexadecimal SHA-256 digest of the UTF-8 standing-code secret (`ci_code_<64 lowercase hex digits>`, minted from 32 cryptographically random bytes via `randomBytes(32)`); the raw code secret is never stored.\
`StandingCodeStore` offers `load(): readonly StandingCodeRecord[]` and `save(records: readonly StandingCodeRecord[]): void`: `createMemoryStandingCodeStore(initialRecords?)` keeps deep-frozen plain records in memory; `createFileStandingCodeStore(filePath, fsOverrides?)` in `@apnex/credential-issuer/machine` (`src/machine-adapter.ts`) inspects `filePath` and `${filePath}.tmp` with `lstatSync` before opening anything, throwing a coded `Error` with `code: "code-store-unwritable"` if either path is a symbolic link or a directory, and on `load()` throwing a coded `Error` with `code: "code-store-corrupt"` before opening `filePath` if `filePath` exists and is any other non-regular file (`!stat.isFile()`, such as a FIFO/named pipe, socket or device, so `load()` never blocks on a non-regular file; returning `[]` when `filePath` is absent with `ENOENT`), then validating `load()`'s UTF-8 lines through `readPlainJson` after a leading `{"store":"credential-issuer-codes","version":1}` header line (throwing `code: "code-store-corrupt"` on any missing/bad header, malformed JSON, non-plain line, invalid field or duplicate `codeId` or `codeHash`, never resetting or resurrecting codes), and committing every `save(records)` synchronously before returning by writing the header and canonical JSON record lines to `${filePath}.tmp` (`O_CREAT | O_EXCL | O_WRONLY`, mode `0600`, unlinking a stale regular `${filePath}.tmp` first if present), calling `fdatasyncSync`, closing the descriptor, calling `renameSync("${filePath}.tmp", filePath)`, and calling `fsyncSync` on the parent directory:
- if any step before or at `renameSync` throws, `filePath` on disk has not been replaced, `save` throws `code: "code-store-unwritable"` (`afterRename: false`), and `mintStandingCode` / `revokeStandingCode` leaves in-memory records unchanged and returns `{ ok: false, code: "code-store-unwritable" }`;
- if `renameSync` succeeds (replacing `filePath` on disk) and the subsequent parent-directory open/`fsyncSync` throws (`code: "code-store-unwritable"`, `afterRename: true`), `credential-issuer` marks its standing-code store **quarantined** for the remainder of the instance's lifetime and returns `{ ok: false, code: "code-store-unwritable" }`, refusing all subsequent `mintStandingCode`, `listStandingCodes`, `revokeStandingCode` (as `{ ok: false, code: "code-store-unwritable" }`) and standing-code `issueAdmissionKey` calls (as `{ ok: false, code: "code-store-unwritable" }`, so a revocation whose directory sync failed can never remain usable in memory) until a fresh `CredentialIssuer` instance recovers authoritatively from `standingCodeStore.load()`.\
`issuer.mintStandingCode({ proof, identity, expiresAtMs? })` rejects any admission key or standing code passed as `proof` (`{ ok: false, code: "proof-refused" }`), verifies `proof` via `caller-identity`'s `verifyCredential(verifiers, proof, { clock })`, checks `isSignInRevoked?({ principal, issuer, session })` (refusing as `"proof-refused"` if unverified, expired or revoked), validates `identity` (`"invalid-identity"`) and optional `expiresAtMs` (`"invalid-expiry"` if non-finite or `<= wallClock.nowMs()`), checks `allowStandingCode({ minterPrincipal, minterIssuer, identity })` (read as a plain boolean via `readPlainJson` and `observePromises`, refusing as `"forbidden-identity"` unless `true`), and in the serialized commit turn re-verifies sign-in revocation and expiry, mints `code = "ci_code_" + hex(randomBytes(32))` and `codeId = "sc_" + hex(randomBytes(8))`, persists via `standingCodeStore.save` before mutating in-memory state, and returns `Object.freeze({ ok: true, codeId, code, identity, minterPrincipal, minterIssuer, createdAtMs, expiresAtMs: expiresAtMs ?? null })`.\
`issuer.listStandingCodes({ proof })` verifies `proof` and `isSignInRevoked` (`"proof-refused"`) and returns `{ ok: true, codes }` with the caller's public `{ codeId, identity, minterPrincipal, minterIssuer, createdAtMs, expiresAtMs, revokedAtMs }` records (never `code` or `codeHash`).\
`issuer.revokeStandingCode({ proof, codeId })` verifies `proof` and `isSignInRevoked` (`"proof-refused"`), requires `codeId` to exist for `(minterPrincipal, minterIssuer)` (`"not-found"`), sets `revokedAtMs` on `wallClock` and persists via `standingCodeStore.save` before updating in-memory state, so a revoked or expired standing code yields no admission key from the moment it is revoked or expires.\
Tested by: `D10-E2`, in `test/contract/standing-code.test.js`, covering sign-in verification, `allowStandingCode` (including `minterPrincipal !== identity`), SHA-256 hashing without raw secret storage, `listStandingCodes`, `revokeStandingCode`, wall-clock expiry, `createMemoryStandingCodeStore` and `createFileStandingCodeStore` across restarts, symlink/directory/pre-rename write-failure `"code-store-unwritable"` fail-closed checks, post-rename directory `fsyncSync` failure quarantining in-memory standing-code operations and recovering on restart, FIFO/non-regular-file and corrupt header/line/duplicate `"code-store-corrupt"` checks before reading, and `D54`/`D55` plain-data callback protection.

**CIss2 - Exclusive node leases, handle reservation accounting and admission-key issuance (`admission-key-issue`, `preshared-key-secret`, `A1`, `D38`, `D39`, `D60` to `D63`, `D71`, `D73`).**\
Active node leases in `credential-issuer` are indexed by **`(hub, node)`** (`D60` item 3, `D61`): at most one `(issuer, principal, instanceBinding)` owns an active lease for a given `(hub, node)` at any time.\
`issuer.issueAdmissionKey(request)` accepts OAuth 2.0 token-exchange requests for sign-in proofs (`grantType: "urn:ietf:params:oauth:grant-type:token-exchange"`, `subjectToken`) and client-credentials requests for standing codes (`grantType: "client_credentials"`, `clientSecret`), as well as `{ proof: { kind: "sign-in", token } | { kind: "standing-code", code } }`, together with `hub`, `node`, optional `proofMode` (`"native-tls13-external-psk-v1"` default, or `"bearer"`), and optional `continuationSecret`.\
It rejects any admission key presented as proof (`{ ok: false, code: "proof-refused" }`), validates `hub === options.hub` (`"wrong-hub"`), `node` format `<identity>.<16 lowercase hex>` (`"invalid-node"`), and `proofMode` (`"invalid-proof-mode"`), and establishes `(principal, issuer)` from the proof:
- for a sign-in proof, `verifyCredential(verifiers, subjectToken, { clock })` and `isSignInRevoked` establish `principal = verified.principal` and `issuer = verified.issuer` (refusing as `"proof-refused"` if unverified, expired or revoked);
- for a standing code (`D39`, `D60`), if the standing-code store is quarantined (`CIss1`), refuses as `"code-store-unwritable"`; otherwise looking up the record by SHA-256 `codeHash` requires `revokedAtMs === null`, `expiresAtMs === null || wallClock.nowMs() < expiresAtMs`, and `record.identity === nodePrefix` (else `"proof-refused"`), and establishes **`principal = record.identity`** (the provisioned identity the code was minted for, even when `record.minterPrincipal !== record.identity`) and **`issuer = record.minterIssuer`** (the canonical authority namespace under which the code was minted; `record.minterPrincipal` remains audit/ownership metadata on the standing code).\
It then checks `allowAdmissionKey({ principal, issuer, hub, node, proofKind, proofMode })` (read as a plain boolean via `readPlainJson` and `observePromises`, refusing as `"policy-refused"` unless `true`).\
In the serialized commit turn, `issueAdmissionKey` re-verifies sign-in expiry and `isSignInRevoked` (or standing-code non-quarantine, non-revocation and wall-clock expiry, refusing if invalidated while awaiting an async callback), sweeps reclaimable leases, expired handle reservations and expired retained keys (`sweepLeases()`), checks `retainedKeys.size < maxRetainedKeys` (else refuses `{ ok: false, code: "lease-capacity" }` without evicting any retained key before its `retainUntilMonotonicMs`), and checks the active lease for `(hub, node)`:
- if no active lease exists for `(hub, node)`, checks `activeLeases.size < maxActiveLeases` and `totalReservedHandles < maxTotalHandles` (else refuses `{ ok: false, code: "lease-capacity" }` without evicting any live lease), allocates a new lease for `(hub, node)` with `issuer`, `principal`, a fresh 32-byte cryptographically random hex `continuationSecret` (`"ci_cont_" + hex(randomBytes(32))`, stored only as its SHA-256 hash), a unique `instanceBinding = "${generation}-${++nextAllocationId}"` (never reused for any later allocation or across restarts), `reservedHandles: 0`, and `lastActivityMs = clock.now()`;
- if an active lease exists for `(hub, node)`, requires `lease.issuer === issuer && lease.principal === principal` and a valid `request.continuationSecret` matching `lease.continuationSecretHash` (refusing any competing `(issuer, principal)` - including the same `principal` spelling under a different `issuer` namespace - or missing/wrong `continuationSecret` for an active `(hub, node)` as `{ ok: false, code: "node-identity-conflict" }`), checks per-lease and total handle capacity (`lease.reservedHandles < maxHandlesPerLease` and `totalReservedHandles < maxTotalHandles`, else `"lease-capacity"`), and advances `lease.lastActivityMs = Math.max(lease.lastActivityMs, clock.now())`.\
**Handle reservation and key retention lifecycle:** each issued key reserves 1 handle slot at issuance (`lease.reservedHandles += 1`, `totalReservedHandles += 1`, `key.reservationHeld = true`) and sets `validBeforeMonotonicMs = issuedAtMonotonicMs + keyLifetimeMs` and `retainUntilMonotonicMs = issuedAtMonotonicMs + keyRetentionMs` on `clock`; when the key is redeemed in `CIss3`, its `"prepared"` -> `"committed"` or `"uncertain"` handle slot inherits that 1 reservation without incrementing `reservedHandles` again (and if `recordAdmissionRedemption` returns an explicit unrecorded refusal, the `"prepared"` slot is removed while the `"unspent"` key keeps its 1 reservation until redeemed or expired); the 1 handle reservation is released (`lease.reservedHandles -= 1`, `totalReservedHandles -= 1`, `reservationHeld = false`, at most once) during `sweepLeases()` either when an `"unspent"` key with no committed/uncertain slot reaches `nowMs >= key.validBeforeMonotonicMs`, or when a `"committed"` or `"uncertain"` slot has both been observed `{ state: "terminal" }` (`slot.terminalObservedAtMs !== null`) and reached `nowMs >= slot.validBeforeMonotonicMs` (at which point the live `lifecycle`/`control` slot is compacted from the lease's handle table while the key record retains its immutable `firstUseSummary: { useId, sessionId }` until `nowMs >= key.retainUntilMonotonicMs`, when `sweepLeases()` deletes the key from `retainedKeys`).\
`issueAdmissionKey` mints `redemptionId = "${generation}-${++nextKeyId}"` (verifying printable ASCII `0x21..0x7E`, no NUL or whitespace, and `utf8ByteLength(redemptionId) <= maxPskIdentityBytes <= 127`, refusing as `"incompatible-psk-identity"` before reserving a handle if `maxPskIdentityBytes` is exceeded), a fresh 32-byte cryptographically random `secret = randomBytes(32)` (`Uint8Array(32)`) together with its 64-character lowercase hex string `secretHex`, `validBeforeMonotonicMs`, `keyFingerprint`, `bearerToken`, `continuationSecret`, and RFC 9068 claims (`iss: issuer`, `sub: principal`, `aud: hub`, `client_id: node`, `jti: redemptionId`, `exp`), returning `Object.freeze({ ok: true, redemptionId, pskIdentity: redemptionId, secret: new Uint8Array(secret), secretHex, bearerToken, proofMode, issuer, principal, hub, node, instanceBinding: lease.instanceBinding, continuationSecret, issuedAtMonotonicMs, validBeforeMonotonicMs, claims })`.\
Tested by: `D10-E2`, in `test/contract/admission-key-issue.test.js` and `test/contract/preshared-key-secret.test.js`, covering RFC 8693 sign-in and `client_credentials` standing-code issuance (including `minterPrincipal !== identity` mapping to `principal === identity` and `issuer === minterIssuer`, and two authorities with the same `principal` spelling), admission-key-as-proof rejection, `isSignInRevoked` rechecked at serialized commit, `(hub, node)` lease exclusivity (`"node-identity-conflict"` on competing `(issuer, principal)` or missing/wrong `continuationSecret`, `"lease-capacity"` without live eviction, and `maxRetainedKeys` capacity), handle-reservation recovery after unused-key expiry, explicit unrecorded refusal, terminal redemption and duplicate sweeps, 32-byte cryptographically random `Uint8Array` `secret` + `secretHex` from `randomBytes(32)` and `<= 127`-byte printable ASCII `pskIdentity`, and `D54`/`D55` plain-data protection.

**CIss3 - Non-consuming PSK lookup, proof completion, single-use termination and reuse reporting (`preshared-key-secret`, `single-use-admission`, `key-reuse-report`, `A2`, `D47`, `D63`, `D71`, `D72`, `D73`).**\
`redeemer.resolvePsk(pskIdentity, attempt?)` (`A2`) synchronously validates `pskIdentity` (non-empty printable ASCII `0x21..0x7E`, `<= maxPskIdentityBytes <= 127` bytes) and looks up the key in the current process `generation`: if the key exists in `retainedKeys` for `proofMode === "native-tls13-external-psk-v1"` and `hub === options.hub` within its retained window (`clock.now() < key.retainUntilMonotonicMs`), including a key already `"spent"`, `"uncertain"` or expired within that retention window, `resolvePsk` returns `{ kind: "resolved", secret: new Uint8Array(key.secret), lookupRef }` (reusing the same `lookupRef` on repeated callbacks for the same `attempt` and `pskIdentity`) without marking an unspent key spent and without reporting reuse or closing any session at lookup time, so a selector-only probe without the 32-byte secret never spends a key, reports reuse or closes a live session, while a second presenter holding the secret completes the handshake and is caught at `completePskProof`.\
`redeemer.completePskProof(attempt, proof)` (and `redeemer.redeemBearer(use, bearerToken, remoteNodeId?)` for `"bearer"` keys) verifies exact object identity (`proof.arrival === attempt.arrival && proof.lookupRef === attempt.lookupRef`) and runs the serialized non-yielding transaction:
1. **Existing `use.lifecycle` registration check first:** before branching on `key.state`, checks whether `use.lifecycle` is already registered in the redeemer's handle table or in `key.refusedReuseLifecycles`: if `use.lifecycle` is already registered for this exact `key.redemptionId`, returns `"redeemed"` when that registration's state is `"committed"` and `"refused"` when its state is `"uncertain"` or when `key.refusedReuseLifecycles.has(use.lifecycle)` (without preparing a new slot, changing reservation counts, calling `recordAdmissionRedemption` or `requestAdmissionTermination` again, or emitting a duplicate `onKeyReuse` report); if `use.lifecycle` is already registered for a different `redemptionId`, returns `"refused"` without preparing anything.
2. **Second presentation (`key.state === "spent" || key.state === "uncertain"` with a distinct `use.lifecycle`):** records `use.lifecycle` in `key.refusedReuseLifecycles` (a `WeakSet<object>`), assigns a distinct non-secret `secondUseId = "${generation}-use-${++nextUseId}"`, refuses the second presentation (`"refused"`), determines `live = clock.now() < key.validBeforeMonotonicMs`, calls `key.firstUse.control.requestAdmissionTermination()` (`agp:session-close`) if and only if `live && key.firstUse !== null`, reads `firstSession` from `key.firstUse?.lifecycle.readAdmissionUse()` when `key.firstUse !== null` or from `key.firstUseSummary.sessionId` after terminal slot compaction (`string | null`, and `secondSession: null`), and emits one frozen `KeyReuseReport` `{ keyFingerprint, redemptionId: key.redemptionId, principal, issuer, hub, node, firstUseId: key.firstUseSummary.useId, secondUseId, firstSession, secondSession, firstRedemptionId: key.redemptionId, secondRedemptionId: key.redemptionId, firstSessionStopped: live && key.firstUse !== null }` to `onKeyReuse` (guarded with `try / catch` and `observePromises`, never exposing the raw key, its 32-byte secret, or the proof that obtained it).
3. **First presentation (`key.state === "unspent"`):** synchronously checks the issuing `generation`, active `(hub, node)` lease (`lease.instanceBinding === key.instanceBinding`), proof mode, target `hub`, `remoteNodeId === key.node` (when provided), and `clock.now() < key.validBeforeMonotonicMs` (returning `"refused"` without `onKeyReuse` if expired), pre-inserts `slot` (with `useId = "${generation}-use-${++nextUseId}"` and state `"prepared"`, inheriting the key's handle reservation), and calls `use.redemption.recordAdmissionRedemption(key.redemptionId, { clock, validBeforeMonotonicMs: key.validBeforeMonotonicMs })` (read through `readPlainJson` and `observePromises`):
   - on `{ kind: "recorded" }`, synchronously flips `slot.state = "committed"`, `key.state = "spent"`, `key.firstUse = slot`, `key.firstUseSummary = { useId: slot.useId, sessionId: null }`, and updates `lease.lastActivityMs = Math.max(lease.lastActivityMs, clock.now())` in place, returning `"redeemed"`;
   - on an explicit unrecorded refusal (`"authorization-expired"`, `"expired"`, `"invalid-authorization"`, `"invalid-redemption"`, `"inactive"`, `"capacity"`) or `"already-recorded"`, removes the newly `"prepared"` slot and leaves `key.state = "unspent"` with its handle reservation intact until redeemed or expired (or preserves the original committed registration on `"already-recorded"`), returning `"refused"`;
   - if `recordAdmissionRedemption` throws or returns any other shape, flips `slot.state = "uncertain"` and `key.state = "uncertain"`, sets `key.firstUse = slot`, `key.firstUseSummary = { useId: slot.useId, sessionId: null }`, calls `use.control.requestAdmissionTermination()` (`observePromises`), and returns `"refused"`.\
`redeemer.beginPskArrival(uses, callbacks, arrival)` (`A2`, `D72`) synchronously calls `uses.reserveAdmissionUse()` before any TLS, lookup or proof work (returning `{ kind: "refused", reason: "capacity" | "inactive" }` when unavailable, and if setup fails before returning an attempt, disposing any partial host work and calling `use.finishAdmissionAcquisition()` immediately without awaiting a carrier callback), and returns an attempt with `resolvePsk(pskIdentity)`, `completePskProof(proof)`, `acceptPskChannel(channel)`, and an independent `carrierAcquisitionSettled()` method (`agp/docs/design/credentialed-peer-acquisition-completion-amendment.md` section 3):
- when a channel is produced, `acceptPskChannel(channel)` is called before `carrierAcquisitionSettled()`, synchronously recording host custody of `channel` and returning normally first while queueing the bounded host continuation (`use.sealAdmissionHandoff(channel)` -> `callbacks.acceptAdmission(seal.handoff)`, or on unredeemed proof, refused seal or throwing `acceptAdmission`, calling `requestAdmissionTermination()` and disposing the host-owned `channel`); the queued host continuation and `carrierAcquisitionSettled()` may then complete in either order, and `use.finishAdmissionAcquisition()` (`compositionSettled`) is called once both have completed, without waiting for node adoption or node-owned channel disposal;
- when an activated attempt produces no channel (`acceptPskChannel` was not called before `carrierAcquisitionSettled()`), `carrierAcquisitionSettled()` revokes any prepared/redeemed slot via `requestAdmissionTermination()` and calls `use.finishAdmissionAcquisition()` once any in-flight host proof work has settled (and any late `acceptPskChannel` after a no-channel `carrierAcquisitionSettled()` is refused and disposes `channel`).\

**CIss4 - Dual lookup and 4-condition lease reclamation (`admission-key-verifier`, `A5`, `D62`, `D63`, `D71`, `D73`).**\
`redeemer.verifyRedeemed({ redemptionId, lifecycle, remoteNodeId })` (`admission-key-verifier`, `A5`) validates its inputs and resolves a redeemed key for `caller-identity` only when its slot is `"committed"` under the current process `generation` and current active `(hub, node)` lease (`lease.instanceBinding === slot.instanceBinding`), both `slot.redemptionId === redemptionId` and exact object identity `slot.lifecycle === lifecycle` match, and `remoteNodeId === slot.node`, returning `Object.freeze({ ok: true, issuer: slot.issuer, principal: slot.principal, instanceBinding: slot.instanceBinding })` (or `{ ok: false, reasonCode: "EXPECTED_NODE_MISMATCH" }` when `remoteNodeId !== slot.node`, or `{ ok: false, reasonCode: "SECURITY_EVIDENCE" }` otherwise, never returning the key or any secret).\
`redeemer.sweepLeases()` polls each registered `slot.lifecycle.readAdmissionUse()` inside `try / catch` through `readPlainJson` and `observePromises`, retaining the slot and lease on `"pending"`, `"admitted"`, `"established"` or any throw or malformed return (updating `key.firstUseSummary = { useId: slot.useId, sessionId }` when `"admitted"` or `"established"` reports a valid `sessionId`), recording `slot.terminalObservedAtMs = nowMs` and advancing `lease.lastActivityMs = Math.max(lease.lastActivityMs, nowMs)` on the first valid `{ state: "terminal" }` observation, releasing the handle reservation (`CIss2`) and compacting terminal slots from the lease's handle table once `nowMs >= slot.validBeforeMonotonicMs` (while preserving `key.firstUseSummary` on the retained key record until `nowMs >= key.retainUntilMonotonicMs`), releasing unused-key handle reservations once `nowMs >= key.validBeforeMonotonicMs`, deleting expired keys from `retainedKeys` once `nowMs >= key.retainUntilMonotonicMs` and their slots are compacted, and reclaiming the lease for `(hub, node)` only when all four `D62` conditions hold together in the same synchronous turn: (1) no `"unspent"` key under `lease.instanceBinding` has `nowMs < key.validBeforeMonotonicMs`, (2) no `"prepared"` or `"uncertain"` or pending/admitted slot under `lease.instanceBinding` remains non-terminal, (3) every `"committed"` slot under `lease.instanceBinding` has been observed `{ state: "terminal" }`, and (4) `nowMs - lease.lastActivityMs >= reconnectGraceMs`, after which a subsequent issuance for `(hub, node)` receives a new, never-reused `instanceBinding`.\

## Fit criteria

### Does my project want this at all

- Clients connect directly to a service and hold their connection open, and the service must decide, as each connection opens, whether to admit it.
- Some clients are people signed in through a provider, and some are machines with no person present.
- A credential stolen from a client, a log or a URL must be worth as little as possible.

### Does it meet my requirement

- A service sees one kind of credential from every client.
- No credential a service accepts admits twice.
- The host chooses its sign-in providers, its verifiers and its rule on who may connect; none is built in.

**It is the wrong tool when**

| You need | Reach elsewhere, because credential-issuer is |
|---|---|
| sign-in pages, accounts or passwords | not an identity provider |
| who a request comes from, request by request | not a verifier of requests; that is caller-identity |
| what a caller may read or change | not an authority; that is the application's policy |
| tokens for many services, consent or delegation | not a general authorization server |
| a protected channel | not a transport |

---

## Adjustment policy

Internal and sovereign, so a fit gap has somewhere to go.

1. Record a measured gap where both sides can see it.
2. Resolve it by adjusting credential-issuer, so every consumer gets the change, or by fracturing it when the gap reveals a second duty.
3. Never fork.

Proofs reach it through verifiers the host supplies, and keys reach a hub through the transport, so a new sign-in provider is a verifier and a new transport profile is a carriage, rather than a change to credential-issuer.
